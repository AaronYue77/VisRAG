项目名字：基于官方商品数据的电商多模态 RAG（A 阶段）
##############################################################################################################

当前定位：偏 AI 应用开发的个人项目。先完成可检查的静态商品资料问答；后续 B 做检索增强、C 做有目标微调，再接电商 Agent。
——————————————————————————————————————————————————————————————————
数据来源要说清楚：
- 官方 Amazon Berkeley Objects（ABO）：147702 条商品元数据，原始格式是 JSON 属性与商品图片。
- 本项目从中选 24 个 CHAIR 商品，生成 24 份两页 PDF 资料卡；原值、单位、原图、源记录位置和 image_id 保留。
- PDF 是转换件，不是厂家原始手册；152 道问答和开发/测试划分是本项目自建，不是官方 ABO 问答标注。
- 8 个第二页作光栅化处理，用于验证 OCR 分支；它们是受控扫描样例，不声称来自真实扫描手册。
- 先按商品去近似和分组，再各取12个开发/测试商品。全部页面和问题随商品一起划分；没有在A训练模型。
- family_key 是本项目启发式组，非官方父SKU。共享主图、型号、相似标题已过滤，未知变体仍是局限。
- 主图看过，原始属性也有异常，例如 color=Pierced Splat Back；来源可靠不代表每个字段都是物理真值。保留原值和问题记录，不偷偷修正。

实际链路与代码入口：

官方原始 JSON/图片
  → abo_data.py download/profile/select：下载、结构检查、固定种子选择、按 image_id 下载原图
  → abo_data.py cards/annotate：原始属性排版PDF、来源页码、人工照片问题和自建评测题
  → stage_a_index.py extract：PyMuPDF 原生文字块；不足20个非空字符触发 RapidOCR
  → chunks：整页或4文字块窗口；候选始终映射 PDF 物理页
  → route：静态资料 / 澄清 / 无资料 / 需要实时工具 / 场外
  → BM25Retriever.search：商品与站点过滤、BM25、父页面去重、跨商品各保留一个候选
  → stage_a.py Reader.read：渲染实际候选页面图片，本地 Qwen3.5-2B 看图，输出 JSON 与页面标签
  → decode_business_output：输出结构、引用范围和拒答保护
  → score / summarize：字段与数值单位、证据页、路由、拒答、耗时、显存；按商品连接组计算CI
  → rag_common/audit.py：results.jsonl + 每次运行逐题结果.txt + 记录/逐题结果汇总.txt

这是一条固定的、有路由的 RAG 工作流；未实现自主规划、ReAct循环、多Agent、MCP或真实业务工具。

图片里的面试问题                         A阶段怎么体现                                      证据与可讲边界

为什么做这个项目？                       帮用户查商品属性、读规格表和图片、比较两个商品        当前24商品152题，解释服务对象与边界；不承诺拿到某公司offer
知识库如何构建？数据从哪来？             官方下载→属性核验→来源卡→页索引→题集隔离             abo_data.py、downloads.json、selection.json、protocol.json
PDF图文分离/版面如何处理？               原生文字块保留坐标；整页图片保存整体图文布局          pages.jsonl 的 blocks/bbox_pt、实际PDF和输入图片
是否实现通用版面/表格解析？              A没有完整重建复杂表格或任意阅读顺序                   已保留文字块和页面图；复杂结构解析可在B按失败加入
什么时候用OCR？为什么不是每页都做？     少文字页触发；正文原生文字优先，控制成本与识别噪声    48页中8页OCR；有/无OCR开发检索对照，不用计划代替结果
切分有什么策略？重叠多少？               整页 vs 4块窗口，0/1块重叠，父页去重                  a-retrieval-dev-grid-v2；重叠未带来额外召回收益
为什么不直接长文全部塞给模型？           限制图片/上下文预算，减少无关商品及冲突数字           Top-1/2/4检索对照；A未做超长上下文压力测试
稀疏/稠密检索是什么？                    A实际使用BM25稀疏词项检索                            k1=1.5、b=.75；BGE/VisRAG属于B对照，不拿模拟融合当真实视觉融合
Top-k太大有什么问题？                   图像token、噪声、生成耗时和显存增加                  单商品只有2页，Top-2已全覆盖；跨商品2页预算才真正暴露排序问题
为什么加业务过滤？                       商品/站点不能串用；未知型号和上下文冲突明确返回      实际规则路由+单位保护测试；带ASIN的显式题未测到过滤召回增益
路由如何实现和评估？                     可解释规则优先；记录action、reason和候选范围          8道开发+8道测试业务边界题及额外单元检查；不是训练的意图分类器
路由是不是Agent？                       当前只选择固定分支                                  requires_tool只返回状态，没有调用或执行订单退款
缺型号、串型号、多商品怎么处理？         澄清、冲突校验；两商品保留各自候选                   实际4道跨商品宽度题；多意图拆解留后续Agent
资料版本和历史日期怎么处理？             快照日期登记；不支持的历史日期明确无对应资料          没有捏造原始发布日期/厂家有效期；模拟过期用例只作回归
怎么防止没找到资料仍编造？               限定图片证据、not_found协议、引用校验                24道缺失电池信息题分开发/测试；不以模型常识回答缺失字段
Prompt有哪些优化？                      保留原始单位、简短JSON、明确引用标签不等于物理页码    blocks-v2 vs labels-v3只改变引用提示，保留收益、代价与剩余错误
怎么验证引用？                           检查标签在候选内，再对照参考页与事实值               合法引用≠正确引用；页码对齐≠完整句子蕴含，原始输出可人工复核
答错来自检索还是模型？                   看候选召回，再在开发集用人工正确页作oracle诊断       8道诊断题；扶手题正确页仍答错，不把oracle计为正式效果
多模态体现在哪里？                       模型读取含商品照片/属性表的真实页面图，有照片扶手题   BM25负责文本找页，VLM负责看图回答；A没有视觉向量检索和视频
图片分辨率与token如何选？                同题196608/786432像素对照，记录grid视觉token          8题有限诊断；没有“像素越大一定越准”的结论
模型怎么选？为什么先不训练？             复用已验证本地2B模型，8GB显存可跑通                 固定revision/greedy/BF16/SDPA；没有做全模型排行榜或从零训练
显存/时间怎么算？                        分开保存模型加载、图片预处理、检索、生成及CUDA峰值    逐题文件和provenance.json；生成P50不含模型冷加载
统计特色是什么？                         同题配对，按相关商品组bootstrap，报告退化和区间        paired-analysis.json；小样本不将改善包装为普遍显著业务收益
指标怎么测？                             Recall/MRR、字段与单位、证据对齐、拒答、路由、P50/P95   正式测试独立76题；模板问答及自动匹配局限写清
如何避免泄漏？                           商品组分割、引用页/答案不进入正常Reader、冻结测试参数  config哈希、input_manifests、source_snapshot；oracle仅开发诊断
增量索引如何处理？                       PDF内容哈希+解析器/OCR版本和权重SHA复用解析缓存        增量缓存验证.txt；BM25全局统计加载时重建，不称向量库增量更新
有没有部署/API？                         有localhost HTTP JSON入口，CLI也可独立提问            /health、/ask；本机验证，不声称已云端生产上线
并发/线程/IO与CPU？                      PDF/OCR主要CPU；下载网络IO；模型GPU；GPU单请求执行     本地API最多2个在途槽，超额429；并发压测和分布式服务未做
用LangChain/LangGraph了吗？              A用直接Python模块清楚表达链路                       没有为了关键词套框架；Agent阶段再按状态/工具需求选LangGraph
最大难点与个人贡献？                     跨商品证据漏召回、标签与物理页混淆、来源字段异常      两组单因素改进及真实失败；不是只改README或复制上游指标

后续阶段再做，不冒充A已实现：

B：BGE稠密、VisRAG-Ret视觉、文字视觉融合、RRF、独立重排、必要时最多一次改写检索；对照相同题集/VLM/预算。
   对应面试：视觉文字如何对齐、余弦/欧氏、Hybrid如何融合、Rerank为什么有效、HyDE、改写如何验证。
C：从正确证据仍答错的任务出发，另建训练环境做LoRA-SFT，对比原提示/改进提示/LoRA；固定B候选。
   对应面试：训练数据、loss masking、LoRA/QLoRA、显存/batch/time、泛化与消融。当前没有训练日志，不能写已微调。
后续电商Agent：真实或明确标注模拟的订单/库存工具、schema参数校验、多轮状态、最大循环次数、超时重试、工具轨迹与权限。
   对应面试：Function Calling、ReAct/Workflow、Planner/Executor、Memory、MCP、多意图、工具成功率和业务兜底。
理论补充：Transformer、ViT、Q-Former/MLP、RoPE/MQA/GQA、交叉熵/KL、常见手写代码；项目不能替代基础学习。
按岗位选学：GRPO/PPO、OPD/跨词表蒸馏、奖励模型/MoE、视频生成；A没有这些实践，不为覆盖面硬加。
